# Executed verification

Lore Plugin 2.5.1 requires completed verification before a reviewed task becomes verified. A caller-written report is insufficient. Commission the checker in the task plan; keep its artifact and source files within the operation root. The verifier label must differ from the executor label. Labels do not prove independent identity.

For deterministic checks, plan a proof_runner with adapter "node-test", path, sha256 and required_tests (the exact Node test names). Optional source_files maps each declared source reference to a local file. The runner reads the received artifact and source contents from the JSON file named by LORE_VERIFICATION_INPUT_FILE. Pin its SHA-256 before execution. All required tests must pass; zero passes, skips, todos, cancelled tests, missing required names and nonzero exit codes reject certification. Node checkers are trusted commissioned code, not a security sandbox. Static import filtering is not a security boundary. Literal presence tests do not establish editorial quality. When the operation owner has criterion, Node is supporting evidence only: configure model "gpt-6-luna" and effort "medium" or "high" in the same proof_runner, with the person’s resource authorization. A completed native review must judge the adequacy of the executed assertions against the criterion before certification. Without that authorization the check stops before model spend; it never falls back to Node certification.

For semantic review, adapter "codex" requires explicit model "gpt-6-luna" and effort "medium" or "high" in proof_runner. Use only with the person's resource authorization. It starts a read-only native Codex execution with the actual artifact and source packet, requires a completed native turn and stores the verdict and execution receipt. Inputs exceeding the current 128,000-byte transported JSON packet limit are refused before spending tokens. This is a model judgment, not a guarantee that every criterion was understood. The packet follows explicit always-on Markdown references and index rows marked always/siempre, including references omitted from the task commission. Missing mandatory files or references outside the operation root reject before execution; source_files can map their normalized references to genuine snapshots inside that root. Conditional routing is judged from supplied contracts and indexes by the native reviewer; it is not mechanically solved for every language or Markdown format. Routed external sources must be supplied as actual local snapshots; a pointer alone is insufficient. A resource or packet-size refusal stays a refusal, never semantic approval.

After receive and review, invoke operation verify with a verifier label. Failure keeps the task reviewed and records executed: true, passed: false and evidence in FASES. Correct, receive and review the result before retrying. CLI certification no longer accepts an observation string as proof. Integration and closure revalidate the bound operation, task commission, artifact, sources, runner and report. Changed inputs invalidate the receipt. The root recorded at reception is part of the signed binding: a checker cannot narrow it to a delivery subdirectory and omit the owner criterion. Inputs and mandatory coverage are rederived before integration and closure. Older receipts without that binding require reconciliation and a fresh receive/review/verification, not silent upgrade.

Execution receipts use a person-local HMAC key under ~/.lore-plugin/verification/execution.key. This detects edited or replayed reports without that key; it cannot protect against the same OS user reading the key or changing trusted code. Receipts attest to this execution path, not universal host identity or agent intelligence. Closure derives incomplete coverage from tasks, pending effects and uncertainty; a recorded partial closure has verified: false and names what remains uncovered.

This verification mechanism leaves the pinned Vespi kernel 0.1.5 unchanged and does not replace the postponed with/without Lore benchmark.

Receipts predating the own-FASES snapshot guarantee can be inspected as historical evidence only. Historical inspection returns certifiesCurrentState: false. Current certification requires an authenticated modern snapshot witness for the same operation and source, revalidated against current prose, authority, criterion and tasks; no silent resealing occurs. Exact duplicate projection preserves every unique field and reconstructs the transported packet before the size gate. Adding a second operation with the real state writer does not invalidate the producer receipt solely because of the insertion separator; substantive prose changes still invalidate it.
