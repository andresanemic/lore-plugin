# Executed verification

Lore Plugin 2.5.2 requires completed verification before a reviewed task becomes verified. A caller-written report is insufficient. Commission the checker in the task plan; keep its artifact and source files within the operation root. The verifier label must differ from the executor label. Labels do not prove independent identity.

For deterministic checks, plan a proof_runner with adapter "node-test", path, sha256 and required_tests (the exact Node test names). Optional source_files maps each declared source reference to a local file. The runner reads the received artifact and source contents from the JSON file named by LORE_VERIFICATION_INPUT_FILE. Pin its SHA-256 before execution. All required tests must pass; zero passes, skips, todos, cancelled tests, missing required names and nonzero exit codes reject certification. Node checkers are trusted commissioned code, not a security sandbox. Static import filtering is not a security boundary. Literal presence tests do not establish editorial quality. When the operation owner has criterion, Node is supporting evidence only: configure model "gpt-6-luna" and effort "medium" or "high" in the same proof_runner, with the person’s resource authorization. A completed native review must judge the adequacy of the executed assertions against the criterion before certification. Without that authorization the check stops before model spend; it never falls back to Node certification.

For semantic review, adapter "codex" requires explicit model "gpt-6-luna" and effort "medium" or "high" in proof_runner. Use only with the person's resource authorization. It starts a read-only native Codex execution with the actual artifact and source packet, requires a completed native turn and stores the verdict and execution receipt. Inputs exceeding the current 128,000-byte transported JSON packet limit are refused before spending tokens. This is a model judgment, not a guarantee that every criterion was understood. The packet follows explicit always-on Markdown references and index rows marked always/siempre, including references omitted from the task commission. Missing mandatory files or references outside the operation root reject before execution; source_files can map their normalized references to genuine snapshots inside that root. Conditional routing is judged from supplied contracts and indexes by the native reviewer; it is not mechanically solved for every language or Markdown format. Routed external sources must be supplied as actual local snapshots; a pointer alone is insufficient. A resource or packet-size refusal stays a refusal, never semantic approval.

After receive and review, invoke operation verify with a verifier label. Failure keeps the task reviewed and records executed: true, passed: false and evidence in FASES. Correct, receive and review the result before retrying. CLI certification no longer accepts an observation string as proof. Integration and closure revalidate the bound operation, task commission, artifact, sources, runner and report. Changed inputs invalidate the receipt. The root recorded at reception is part of the signed binding: a checker cannot narrow it to a delivery subdirectory and omit the owner criterion. Inputs and mandatory coverage are rederived before integration and closure. Older receipts without that binding require reconciliation and a fresh receive/review/verification, not silent upgrade.

Execution receipts use a person-local HMAC key under ~/.lore-plugin/verification/execution.key. This detects edited or replayed reports without that key; it cannot protect against the same OS user reading the key or changing trusted code. Receipts attest to this execution path, not universal host identity or agent intelligence. Closure derives incomplete coverage from tasks, pending effects and uncertainty; a recorded partial closure has verified: false and names what remains uncovered.

The 2.5.3 release draft also binds integration to the real destination file inside the received project root. Place an identical copy of the verified artifact there before calling `integrate`; the command checks its SHA-256 and records the resolved path. A composed or edited deliverable must be received, reviewed and verified as its own task before integration. Closure and `trust` read the destination again: changed, missing, unreadable or out-of-root destinations invalidate current coverage. This detects changes present at the check; it does not prevent arbitrary later writes by the same OS user or establish semantic quality from a digest. Historical integration records without destination evidence cannot certify current closure. For an open operation whose verification still passes, call `integrate` again to explicitly check and bind the current destination. Closed operations remain historical and cannot be reintegrated.

Lore Plugin 2.5.3 pins Vespi kernel 0.1.8 at commit `e7f00b7d9a4c512aca32eda053774a11713bd6c1`; the verification mechanism does not mutate that copy and does not replace the postponed with/without Lore benchmark.

Receipts predating the own-FASES snapshot guarantee can be inspected as historical evidence only. Historical inspection returns certifiesCurrentState: false. Current certification requires an authenticated modern snapshot witness for the same operation and source, revalidated against current prose, authority, criterion and tasks; no silent resealing occurs. Exact duplicate projection preserves every unique field and reconstructs the transported packet before the size gate. Adding a second operation with the real state writer does not invalidate the producer receipt solely because of the insertion separator; substantive prose changes still invalidate it.

The 2.5.3 release draft adds declared final outputs. `operation outputs` records the composed results the commission asks for — id, in-root path, criterion and sources — once, fingerprinting them together with the working goal, intent and obligation descriptions. The fingerprint and the first trail note detect an edited manifest only when the edit does not recalculate them; the same OS user can rewrite the manifest, its fingerprint and the trail note together and closure will accept it. Declaring obligations after the final outputs recomputes the fingerprint and its note; editing the obligation list by hand still invalidates closure. `plan` binds a composition task to a declared output only if its path, criterion and sources match, and one output admits exactly one live task: a second live task for the same output is rejected at planning. A final task is never certified by a node-test runner or by the in-process test double (`executeVerification(..., { nativeRunner })`, sealed as adapter "test-double"): it requires a completed codex receipt, so a length-and-hash assertion cannot pass off an unwritten composition. A final must be planned with the codex adapter: the combined node + authorized Luna route that the design allows is not supported by this candidate, which always rejects node-test for a final output. Closure re-reads each declared output's integrated destination and names the output that is missing, unintegrated or changed. Because the verifier shares the orchestrator's OS user, closure records independence "deteccion-sin-independencia" and stays partial. Detection is not prevention: a terminal overwrite of a declared destination or a manifest edited without recalculating its fingerprint and trail note is detected at closure, never prevented, and an edit accompanied by a recomputed fingerprint and note is not detected. Two concurrent `operation outputs` calls can both report success and one manifest can be lost: the state writer does not compare-and-swap, a race that predates final outputs and also affects obligations. An operation with two or more tasks and no declared final outputs, including a fabricated empty list, closes partial with final-outputs:undeclared.

Method delivery in this release draft uses the shipped method and commission, including goal, sources, scope, done criterion and limits. The Claude Code delivery observer checks the effective prompt or the pinned kit-worker definition and records pre/post hooks before delivery is confirmed. Current delivery evidence is limited to the kit worker on Claude Code; advisor, daimon and the other hosts do not inherit that evidence. Delivery is distinct from behavioral compliance and does not establish causation. Declared obligations retain the original mandate: an artifact passing its tests cannot satisfy a different omitted obligation. Human attestation remains distinguishable from executed evidence.
