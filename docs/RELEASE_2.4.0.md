# Lore Plugin 2.4.0 — Loose notes, one less skill

> [README](https://github.com/andresanemic/lore-plugin#readme) · [Español](#español)

Loose-note mining now belongs to `save-to-lore`, reducing the public surface from eight to seven skills without removing the workflow. Requests about `notes/`, `notas/`, `apuntes/`, `.md`, `.txt` or `.docx` load a separate app-neutral procedure only when needed; Obsidian remains one possible editor, never a prerequisite.

The procedure still sweeps the whole inbox, reports debt, classifies four buckets, waits at the human threshold, writes `destilado:` and archives without deleting. Binary `.docx` sources keep byte-for-byte integrity through a traceable sidecar, and the note flow never commits automatically. The documented RED scenario and its post-REFACTOR fresh-agent check are recorded at [`bench/writing-skills-2.4.0/README.md`](https://github.com/andresanemic/lore-plugin/blob/main/bench/writing-skills-2.4.0/README.md).

Existing Lore needs no migration. Integrations that invoke `obsidian-lore` directly must route note requests to `save-to-lore`; installed copies still require their normal manual synchronization.

Full notes: https://github.com/andresanemic/lore-plugin/releases/tag/v2.4.0

# Lore Plugin 2.4.0 — Notas sueltas, una skill menos

> [README](https://github.com/andresanemic/lore-plugin/blob/main/README.md#español)

El minado de notas sueltas ahora pertenece a `save-to-lore`, reduciendo la superficie pública de ocho a siete skills sin perder el flujo. Las peticiones sobre `notes/`, `notas/`, `apuntes/`, `.md`, `.txt` o `.docx` cargan un procedimiento separado y neutral a la aplicación solo cuando hace falta; Obsidian queda como un editor posible, nunca como requisito.

El procedimiento sigue barriendo la bandeja completa, reportando deuda, clasificando cuatro cubetas, esperando el umbral humano, escribiendo `destilado:` y archivando sin borrar. Las fuentes binarias `.docx` conservan sus bytes mediante un sidecar trazable, y el flujo de notas nunca hace commit automático. El RED documentado y su verificación con un agente fresco después de REFACTOR quedan registrados en [`bench/writing-skills-2.4.0/README.md`](https://github.com/andresanemic/lore-plugin/blob/main/bench/writing-skills-2.4.0/README.md).

El Lore existente no necesita migración. Las integraciones que invoquen `obsidian-lore` directamente deben enrutar las peticiones de notas a `save-to-lore`; las copias instaladas conservan su sincronización manual habitual.

Notas completas: https://github.com/andresanemic/lore-plugin/releases/tag/v2.4.0
