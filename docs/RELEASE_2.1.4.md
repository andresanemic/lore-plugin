# Lore Plugin 2.1.4 — The upgrade of a tree is a map, not a reread

> [README](https://github.com/andresanemic/lore-plugin#readme) · [Español](#español)

2.1.4 teaches `transmute-lore` UPGRADE how to raise an already-installed ecosystem without rewriting what was earned. The four finding kinds were already enough. What was missing was the cheap order: map git roots and `lore/` first, grep before reading, rename only where the text still commands, repair a long index by its header, and reuse accepted finding classes across a campaign.

This number is **2.1.4**, not 2.2. 2.2 stays free. After installing: **new session**.

## What 2.1.4 takes out

The kit got smaller on purpose. Live docs and `create-bot` no longer sell extras that were not the product:

- **A bot is not packaged as a shareable plugin.** No marketplace wrap, no `validar.js` gate, no second contract to install. A bot is a folder you open.
- **Packaging is crystallization.** `transmute-lore` CRYSTALLIZE writes one Markdown; unpacking rebuilds the folder, including `lore-ecosistema/`. That copy is not an extra you turn on when creating the bot. CRYSTALLIZE itself did not change.
- **Telegram is out** of skills and live docs. Creating a bot does not add a phone channel.
- **`research-lus` and Lore in the Shell are out** of Lore Plugin documentation. Their GitHub repos are archived. They are not suggested and they do not come back.
- **The README no longer chooses your contract** (`CLAUDE.md` vs `AGENTS.md`, fallback, pointer adapter). One host-selected contract is enough; the chooser paragraph is gone.

## What 2.1.4 makes clearer

- A graft **takes root** or it is rejected. It is not transplanted to another soil, and in Spanish it no longer «prende».
- The fourteen case studies are written so a reader who has never used the kit can follow them. Kit words are explained once.
- Alchemy/science (`distill`, `crystallize`), garden (`takes root`, scars), and lore stay in their own registers.

## What UPGRADE learned

- UPGRADE maps the tree before it reads a module. A work session with no `lore/` beside it is not «no Lore» if the body lives in the parent.
- In a live `.md` that still commands, `HARD-GATE` is said as threshold. Dated records and another skill's files stay.
- A superseded mode name is renamed in the present tense; dated records stay.
- A long index gets a format header. Its rows are not rewritten on that pass.
- A missing `identidad.md` or `principios.md` is ADD, reported, not invented.
- In a campaign the threshold is per class, not per tree.
- The notes inbox is counted. It is mined only when a note constrains *this* upgrade.

A paragraph is a paragraph (already in the writing skills). This release documents it; it does not reintroduce it.

## What this is not

Not a new mode. Not a 2.1.5. The public case of the mass upgrade is Case 14, in `CASES_{en,es}.md`. Not a scientific transfer.

# Lore Plugin 2.1.4 — El upgrade de un árbol es un mapa, no una relectura

> [README](https://github.com/andresanemic/lore-plugin/blob/main/README.md#español)

La 2.1.4 enseña a `transmute-lore` UPGRADE a subir un ecosistema ya instalado sin reescribir lo ganado. Las cuatro clases de hallazgo ya alcanzaban. Lo que faltaba era el orden barato: mapear gits y `lore/` primero, grepear antes de leer, renombrar solo donde el texto aún manda, reparar un índice largo por su cabecera, y reusar las clases aceptadas en una campaña.

El número es **2.1.4**, no 2.2. El 2.2 sigue suelto. Tras instalar: **sesión nueva**.

## Qué saca la 2.1.4

El kit se hizo más chico a propósito. Los docs vivos y `create-bot` ya no venden extras que no eran el producto:

- **Un bot no se empaqueta como plugin compartible.** Nada de marketplace, nada de `validar.js`, nada de un segundo contrato para instalar. Un bot es una carpeta que abres.
- **Empaquetar es cristalizar.** `transmute-lore` CRYSTALLIZE escribe un Markdown; extraer reconstruye la carpeta, incluido `lore-ecosistema/`. Esa copia no es un extra que se enciende al crear el bot. CRYSTALLIZE no cambió.
- **Telegram queda fuera** de skills y docs vivos. Crear un bot no añade un canal de teléfono.
- **`research-lus` y Lore in the Shell quedan fuera** de la documentación de Lore Plugin. Sus repos de GitHub están archivados. No se sugieren y no vuelven.
- **El README ya no elige tu contrato** (`CLAUDE.md` vs `AGENTS.md`, fallback, adaptador). Un solo contrato según el host basta; el párrafo selector se fue.

## Qué aclara la 2.1.4

- Un injerto **echa raíces** o se rechaza. No se trasplanta a otra tierra, y ya no «prende».
- Los catorce casos se leen sin haber usado el kit. Las palabras del oficio se explican una vez.
- Alquimia/ciencia (`destilar`, `cristalizar`), jardín (`echa raíces`, cicatrices) y lore se quedan cada uno en su registro.

## Qué aprendió UPGRADE

- UPGRADE mapea el árbol antes de leer un módulo. Una sesión de trabajo sin `lore/` al lado no es «sin Lore» si el cuerpo vive en el padre.
- En un `.md` vivo que manda, `HARD-GATE` se dice umbral. El registro fechado y los archivos de otra skill se dejan.
- Un nombre de modo superado se renombra en presente; el registro fechado se deja.
- Un índice largo recibe cabecera de formato. Sus filas no se reescriben en esa pasada.
- Falta `identidad.md` o `principios.md` es ADD, se reporta, no se inventa.
- En una campaña el umbral es por clase, no por árbol.
- La bandeja de notas se cuenta. Se mina solo si una nota restringe *este* upgrade.

Un párrafo es un párrafo (ya está en las skills de escritura). Esta versión lo documenta; no lo vuelve a enseñar.

## Qué no es

No es un modo nuevo. No es una 2.1.5. El caso público del upgrade masivo es el Caso 14, en `CASES_{en,es}.md`. No es un traspaso científico.
