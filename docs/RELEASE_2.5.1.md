# Lore Plugin 2.5.1 — Conservar el acuerdo en cada corrección

> [README](https://github.com/andresanemic/lore-plugin#readme) · [English](#lore-plugin-251--keep-the-agreement-through-each-correction)

Borrador de Lore Plugin 2.5.1; publicación pendiente. El coordinador recomienda una forma de trabajar desde el acuerdo, el criterio pertinente y las skills observadas; conserva la elección de la persona al retomar la operación. Cambiar agente o modelo no concede autoridad nueva.

La revisión exige un veredicto explícito sobre los bytes entregados. El rechazo bloquea la verificación; una corrección conserva el veredicto y la evidencia anteriores. Cerrar exige trabajo verificado de manera independiente e integrado. La interacción y la experiencia declarada por la persona quedan separadas del resultado de una prueba.

Este trabajo se prueba en fixtures locales de repositorio para Claude Code, Codex y OpenCode; eso no certifica el uso instalado ni el release completo. Guía de migración: conserva una copia de cada FASES.md y sus recibos antes de actualizar el plugin; primero instala el candidato en un HOME aislado. Reanuda el mismo ID de operación y revisa autoridad, alcance, siguiente acción y SHA del artefacto recibido antes de actuar. Un recibo de ejecución antiguo queda histórico si cambian la autoridad o la prosa gobernante; verifica de nuevo la tarea actual. Este borrador no autoriza instalación o publicación ni hace migración automática. El informe final de cobertura queda en los registros locales de decisión del release.

El candidato añade un adaptador para OpenCode 2 junto a la entrada server de OpenCode 1. Se observó carga instalada en un HOME aislado de OpenCode 2.0.23; aislamiento multisesión y limpieza se comprueban por separado. La guardia lleva criterio al modelo; el host aplica los permisos de archivos. La matriz de aceptación de los tres hosts sigue incompleta.

Evidencia actual de hosts: OpenCode produjo el andamiaje y HTML sintéticos mediante herramientas nativas de skills y archivos; Codex completó SessionStart y siete PostToolUse y leyó seis archivos permitidos en un HOME aislado. Estas observaciones cubren las acciones ejecutadas. La instalación de Claude pasó la comprobación local del instalador, pero la prueba conversacional devolvió límite semanal antes de generar tokens. Por decisión del dueño del release, esa prueba de Claude se aplaza hasta recuperar cuota; la compatibilidad sigue sin comprobarse. No se declara invocación nativa de PreToolUse, PreCompact ni Skill en Codex.

El catálogo de skills, la interpretación de fuentes consultadas, el efecto de cartas y la aceptación son atestaciones del coordinador. Los recibos firmados comprueban ejecución registrada y bytes entregados; no certifican verdad de dominio ni experiencia de la persona. La clasificación de cartas sigue la regla aprobada de evidencia posterior; evidencia insuficiente o contradictoria queda pendiente. Una comparación local emparejada ejerció un consumidor existente con Stellar SDK: JSON firmado válido fue rechazado y XDR firmado fue aceptado, con seis controles negativos. Un caso separado de borrador local descartó blockchain. Esto muestra una diferencia acotada de formato/puerto, no liquidación, consenso ni superioridad frente a una IA usando ese SDK. La campaña local ahora enlaza creación nativa del proyecto, HTML verificado de forma independiente, criterio persistido, retorno a una segunda decisión, consulta de fuente primaria y arbitraje posterior de carta. Sus cinco comprobaciones de mecanismo pasaron con participantes explícitamente sintéticos; esto no declara un encuentro humano ni fertilidad. Stradale 33 sigue como campaña pendiente de aceptación hasta pasar la revisión independiente final.
